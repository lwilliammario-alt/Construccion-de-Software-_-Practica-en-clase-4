DESCRIPCION GENERAL DEL PROYECTO
---------------------------------
ConstruSoftTicket es una aplicacion web full-stack para el registro de tickets
(solicitudes o reportes de problemas). Usa una arquitectura limpia (Clean
Architecture) en el backend con .NET 8 y una interfaz en React 19 + Vite.

TECNOLOGIAS UTILIZADAS
-----------------------
Backend  : C# / .NET 8 / ASP.NET Core / Entity Framework Core 8
Base de datos : PostgreSQL (via Npgsql)
Frontend : React 19 + Vite / JavaScript (JSX)
Estilos  : CSS (variables CSS, modo oscuro automatico)
Doc. API : Swagger (Swashbuckle)
ORM      : Entity Framework Core con migraciones

  Propiedades:

    - Titulo      (string)   : Titulo o asunto del ticket
    - Descripcion (string)   : Detalle del problema o solicitud

------------------------------------------------------------------------
CARPETA: ConstruSoftTicket.Application/
------------------------------------------------------------------------
Que es:
  La capa de APLICACION. Contiene los casos de uso del sistema:
  servicios, interfaces y DTOs. Orquesta la logica de negocio sin
  conocer detalles de base de datos ni del framework web.

Dependencias: Referencia a ConstruSoftTicket.Domain (solo entidades)

  --- Archivo: ConstruSoftTicket.Application.csproj ---
  Archivo de proyecto de .NET.
  Define dependencia hacia el proyecto Domain.
  No instala paquetes NuGet propios.

  --- Archivo: DTOs/CreateTicketDto.cs ---
  DTO = Data Transfer Object (Objeto de Transferencia de Datos).

  Que hace:
    Define el contrato de los datos que el cliente (frontend) debe
    enviar al crear un ticket. Solo expone los campos necesarios,
    ocultando Id y FechaCreacion que los genera el sistema.

  Propiedades:
    - Titulo      (string): Titulo enviado por el usuario
    - Descripcion (string): Descripcion enviada por el usuario

  Por que existe:
    Evita exponer directamente la entidad Ticket en la API, lo que
    podria causar problemas de seguridad o binding no deseado.

  --- Archivo: Interfaces/ITicketRepository.cs ---
  Que hace:
    Define el CONTRATO (interfaz) que debe cumplir cualquier clase
    que implemente el repositorio de tickets.

  Metodo declarado:
    - Task AddAsync(Ticket ticket)
      Agrega un ticket a la fuente de datos de forma asincrona.

  Por que existe:
    Desacopla la logica de negocio (Application) del acceso real a
    datos (Infrastructure). El servicio depende de esta interfaz, no
    de la implementacion concreta, facilitando pruebas y cambios.

  --- Archivo: Interfaces/ITicketService.cs ---
  Que hace:
    Define el CONTRATO del servicio de tickets que el controlador
    utilizara mediante inyeccion de dependencias.

  Metodo declarado:
    - Task<string> CreateTicketAsync(CreateTicketDto dto)
      Crea un ticket y retorna un mensaje de confirmacion.

  Por que existe:
    Permite que el controlador dependa de una abstraccion, no de una
    implementacion concreta, siguiendo el principio de inversion de
    dependencias (SOLID - D).

  --- Archivo: Services/TicketService.cs ---
  Que hace:
    Implementacion concreta de ITicketService. Contiene la logica de
    negocio real para crear un ticket.

  Proceso interno:
    1. Recibe el DTO con los datos del cliente.
    2. Crea un objeto Ticket (entidad del dominio) con esos datos.
    3. Llama al repositorio para persistir el ticket en la BD.
    4. Retorna el mensaje "Ticket registrado correctamente."

  Dependencia inyectada:
    - ITicketRepository: para guardar el ticket en la BD.

  Archivo vacio generado por Visual Studio. Puede eliminarse.

  Registra los paquetes NuGet de EF Core y Npgsql, y las referencias

  --- Archivo: Data/AppDbContext.cs ---
  Que hace:
    Es el CONTEXTO DE BASE DE DATOS de Entity Framework Core.
    Representa la conexion a PostgreSQL y administra las entidades.

  Hereda de: DbContext (clase base de EF Core)

  Propiedades:
    - Tickets (DbSet<Ticket>): representa la tabla "Tickets" en la BD.
      Permite ejecutar consultas LINQ sobre esa tabla.

  Por que existe:
    EF Core necesita un DbContext para saber que entidades mapear a
    tablas, gestionar transacciones y ejecutar consultas SQL.

  --- Archivo: Repositories/TicketRepository.cs ---
  Que hace:
    Implementacion concreta de ITicketRepository.
    Se encarga de guardar tickets en la base de datos PostgreSQL.

  Metodo implementado:
    - AddAsync(Ticket ticket):
        1. Llama a _context.Tickets.AddAsync(ticket)
           -> marca el ticket como "pendiente de insertar" en EF Core
        2. Llama a _context.SaveChangesAsync()
           -> ejecuta el INSERT SQL real en PostgreSQL

  Dependencia inyectada:
    - AppDbContext: el contexto de base de datos.

  --- Carpeta: Migrations/ ---
  Que es:
    Carpeta generada automaticamente por EF Core al ejecutar el
    comando "dotnet ef migrations add".

  Archivos dentro:
    - 20260424001654_InitialCreate.cs
      La migracion inicial. Contiene los metodos Up() y Down().
      Up()  : crea la tabla "Tickets" con sus columnas en PostgreSQL.
      Down(): elimina la tabla "Tickets" (para revertir).

    - 20260424001654_InitialCreate.Designer.cs
      Archivo de metadatos generado automaticamente por EF Core.
      Contiene el snapshot del modelo en el momento de la migracion.
      No se edita manualmente.

    - AppDbContextModelSnapshot.cs
      Snapshot actual del modelo de datos.
      EF Core lo usa para calcular que cambios hay entre migraciones.
      Se actualiza automaticamente con cada nueva migracion.

ARCHIVO: src/pages/CreateTicket.jsx
------------------------------------------------------------------------
Que es:
  El componente principal y unico formulario de la aplicacion.
  Permite al usuario registrar un nuevo ticket enviando datos al backend.

Estado (useState):
  - titulo      : almacena el texto del campo Titulo del formulario
  - descripcion : almacena el texto del campo Descripcion del formulario

Funcion handleSubmit (asincrona):
  Se ejecuta cuando el usuario hace clic en "Registrar".
  Proceso:
    1. Previene el reload de pagina (e.preventDefault()).
    2. Construye el objeto ticket con titulo y descripcion del estado.
    3. Hace un fetch POST a http://localhost:5139/api/ticket con el
       ticket serializado en JSON.
    4. Lee la respuesta como texto (para evitar errores si no es JSON).
    5. Si la respuesta no fue OK (error HTTP), muestra alerta de error.
    6. Si fue OK, intenta parsear el JSON y muestra el mensaje de exito.
    7. Limpia los campos del formulario (setTitulo(""), setDescripcion("")).
    8. Si hay error de red (sin conexion), muestra alerta de error.

Interfaz renderizada:
  - Contenedor div con padding de 20px
  - Titulo <h2>: "Registro de Ticket"
  - Formulario con:
      * Input type="text"    para el titulo (controlado, requerido)
      * Textarea             para la descripcion (controlada, requerida)
      * Boton type="submit"  "Registrar" para enviar el formulario

FLUJO DE DATOS COMPLETO - COMO FUNCIONA EL SISTEMA
================================================================================

1. El usuario abre el navegador en http://localhost:5173
2. Vite sirve el index.html -> carga main.jsx -> monta <App /> -> muestra CreateTicket
3. El usuario escribe un titulo y descripcion en el formulario
4. El usuario hace clic en "Registrar"
5. CreateTicket.jsx ejecuta handleSubmit:
     - Construye { titulo, descripcion }
     - Envia HTTP POST a http://localhost:5139/api/ticket con JSON
6. La solicitud llega al backend .NET:
     - El middleware CORS valida que viene de localhost:5173 (OK)
     - ASP.NET Core enruta la solicitud a TicketController.Create()
     - El model binding deserializa el JSON a CreateTicketDto
7. TicketController llama a ITicketService.CreateTicketAsync(dto)
8. TicketService recibe el DTO:
     - Crea un objeto Ticket con titulo y descripcion del DTO
     - La FechaCreacion se asigna automaticamente a DateTime.UtcNow
9. TicketService llama a ITicketRepository.AddAsync(ticket)
10. TicketRepository ejecuta:
      - _context.Tickets.AddAsync(ticket) -> EF Core prepara el INSERT
      - _context.SaveChangesAsync() -> EF Core ejecuta el SQL en PostgreSQL
11. El ticket queda guardado en la tabla "Tickets" de PostgreSQL
12. El servicio retorna "Ticket registrado correctamente."
13. El controlador retorna HTTP 200 OK con { "mensaje": "Ticket registrado correctamente." }
14. El frontend recibe la respuesta, parsea el JSON y muestra un alert con el mensaje
15. El formulario se limpia (titulo y descripcion vuelven a string vacio)
